.venv 虚拟环境管理

虽然还没到依赖互相打架的地步，但好习惯要提前养成，这样传Github的也不至于是依托彻底的大粪

Yank/ 2 MIN READ

ON THIS PAGE

正文创建与激活依赖管理清理与重建

记录探索，
也记录过程。

刚开始全都是全局pip装包，万一某个项目要 requests 2.x、另一个要 3.x，装来装去把系统环境搞成一锅粥。

创建与激活

Python 3.3+ 自带 venv 模块，不需要额外安装。在项目根目录执行：

python -m venv .venv

Windows 下激活：.venv\Scripts\activate

激活后命令行提示符会多出 (.venv) 前缀，这时 pip install 装的所有包都会进到 .venv 里，而不是全局。

依赖管理

装好依赖后立刻导出清单，方便换机器或重建环境：

pip freeze > requirements.txt

换到新环境后一条命令装回来：pip install -r requirements.txt。requirements.txt 应该提交到 git，这样别人克隆仓库后能一键复现。

清理与重建

.venv 目录本身不提交到 git（加进 .gitignore 即可）。如果环境装坏了，最省事的办法是直接删掉重建：

rm -rf .venv 然后重新 python -m venv .venv

反正依赖都在 requirements.txt 里，重建成本很低。这也是"一切皆可重来"的底气。
